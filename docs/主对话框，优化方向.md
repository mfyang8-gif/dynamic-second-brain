**1. 优先猛攻 A：引用角标（Citation Markers）**

- **价值**：这是 NotebookLM 的**灵魂**！没有引用角标，它就是一个普通的套壳 ChatGPT。有了角标，它才是严谨的“知识库助手”。
- **性能影响：零损耗。** 你完全不需要修改任何耗时的底层逻辑。
- **实现思路（极简优雅）**：
  1. 你现在的 `PageRagRetrievalService` 已经给每个 Chunk 编了号（`displayIndex`）。
  2. 你只需要在 `buildContextString` 中，告诉大模型：“引用时，请务必在句子末尾加上对应的来源编号，如 [1]、[2]”。
  3. 前端在渲染 Markdown 时，写一个正则表达式 `\[(\d+)\]`，把它替换成一个带有 Hover 效果的超链接卡片即可。

**2. 顺手搞定 E：Prompt 工程优化**

- **价值**：大模型的“智商”上限是由 Prompt 决定的。
- **性能影响：零损耗。**
- **实现思路**：在指导 LLM 生成答案的 System Message 中加入思维链（CoT, Chain of Thought）约束。比如要求大模型：“在回答前，请先在 `<thinking>` 标签内简要梳理你的逻辑结构，然后再给出最终答案”。这能极大地提升长篇阅读和逻辑推理的准确率。

**3. 补充完善 D：多轮对话感知检索**

- **价值**：解决“指代消解”问题（比如用户上一轮问“羊群效应”，这一轮问“它有什么危害”，如果不把“它”还原成“羊群效应”，检索出来的结果全是错的）。
- **性能影响：极小（<300ms）。**
- **实现思路**：在调用 RAG 之前，把最近 3 条历史记录和当前问题丢给一个**极小极快**的模型（如 Qwen-Turbo 或专用改写模型），要求它只输出一句话：“将当前问题补全为完整问句”。
