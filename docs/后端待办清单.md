# 后端待办清单（前端占位功能对接）

> 创建：2026-10-10 深夜。来源：前端「状态机流式动效」与「引用详情」两轮开发中
> 明确留下的后端缺口。每项都给出建议接口签名、请求/响应结构与验收标准，
> 后端实现时请遵循与历史消息接口（见《归档/审核-历史消息接口实现.md》）相同的
> 四条安全红线：
>
> 1. **userId 一律从 token 解析**，请求体/查询参数里出现 userId 字段一律忽略；
> 2. 一切资源访问先过**归属校验**（不属于当前用户 → 403，不存在 → 也回 403，
>    不泄露资源是否存在）；
> 3. 参数校验用 `@Validated` + DTO 注解，非法值回 400；
> 4. 响应不暴露 deleted / 内部状态列。

---

## 1. 引用原文接口（优先级：高）

**背景**：引用详情面板目前展示的是 SSE `done` 事件里的 `textSnippet`
（检索命中片段，前端已改为 markdown 渲染）。底部提示文案写明
「后端暂未提供原文接口」。原文接口就绪后，前端把提示换成
「查看原文」并接入本接口。

**建议签名**

```
GET /api/v1/messages/{messageId}/references/{index}/original?pageNum=1&pageSize=1
```

**说明**

- `messageId` + `index`（引用序号）定位一条引用；也可改为直接以
  `pageId + chunkIndex` 定位（与 SSE `done` 事件的
  `sourceReferences[]` 字段对齐），二选一，定稿后同步前端。
- 返回该命中片段所在的**完整原文分块**（或所属文档该分块前后各一块的拼接，
  便于阅读上下文）。

**响应 VO 建议**

```json
{
  "code": 0,
  "data": {
    "pageId": "p1",
    "docTitle": "梯度下降算法及其改进方法详解",
    "chunkIndex": 0,
    "content": "完整分块原文（markdown）",
    "prevChunkPreview": "上一块末尾 100 字（可空）",
    "nextChunkPreview": "下一块开头 100 字（可空）"
  }
}
```

**验收标准**

- [ ] 无 token → 401；伪造 userId 参数 → 被忽略且行为不变；
- [ ] messageId / pageId 不属于当前用户 → 403；
- [ ] index 或 chunkIndex 越界 → 400；
- [ ] `content` 为完整分块文本，非空截断；
- [ ] 分页参数沿用 `PageQueryDTO` 约定。

## 2. 重新生成（优先级：高）

**背景**：前端操作栏「重新生成」按钮已就位，点击后 emit
`regenerate` 事件并弹 toast「触发重新生成 (后端接入中)」，
`handleRegenerate` 内预留了接入点。

**建议签名**

```
POST /api/v1/sessions/{sessionId}/regenerate
Content-Type: application/json

{ "messageId": 12345 }
```

**语义**

- `messageId` 指向要重新生成的 assistant 消息；后端截断该消息及其之后的
  消息（软删除），以该消息之前的上下文重新发起一次 SSE 流式回答。
- 复用现有 `/v1/chat/stream` 的 SSE 事件协议（status / message / done /
  suggestions），前端渲染管线零改动。

**响应**：与聊天流一致的 SSE；或先回 200 再由前端另起 stream 连接
（二选一，定稿后同步前端）。

**验收标准**

- [ ] sessionId / messageId 归属校验（四红线）；
- [ ] 被截断的消息是软删除，审计可查；
- [ ] 重新生成不重复计费/计数（如有额度机制）；
- [ ] 流式中断（客户端断开）时与现有 chat/stream 的清理行为一致。

## 3. 点赞 / 点踩反馈（优先级：中）

**背景**：前端操作栏赞/踩按钮已就位，互斥 toggle，状态在
`isLiked` / `isDisliked` 响应式变量里，toast 为「反馈已记录 (本地占位)」。

**建议签名**

```
POST /api/v1/messages/{messageId}/feedback
Content-Type: application/json

{ "feedback": "like" }        // like | dislike | none（none = 取消）
```

**说明**

- 幂等：重复提交同值不报错；`none` 清除反馈。
- 同一消息同一用户只有一条反馈记录（upsert）。

**验收标准**

- [ ] messageId 归属校验（必须是对当前用户可见的 assistant 消息）；
- [ ] `feedback` 取值白名单校验，非法值 400；
- [ ] 重复点击 / 取消后再点，最终状态与前端一致；
- [ ] 返回 `{ "feedback": "like" }` 的当前生效值，便于前端对账。
