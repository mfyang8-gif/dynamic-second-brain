# B1 写入链测试方案（Phase 4 · Graphiti 记忆微服务集成）

> 对应代码：`feat/async-ingestion-pipeline` @ `a888883`
> 覆盖范围：B1「Graphiti 写入链」全部新增/修改的 30 个文件
> 目标：把「静默数据丢失」类缺陷从**靠人看**变成**靠机器拦**

---

## 一、为什么 B1 需要一份专门的测试方案

B1 这条链路有一个和其他模块不同的性质：**它的大部分失败模式是静默的**。

举三个已经发生或险些发生的事实：

| 事实 | 若不测会怎样 |
| --- | --- |
| `LocalDateTime.MIN` 超出 MySQL DATETIME 定义域 | 发现层对**全新会话**完全不工作，对外只表现为「记忆一直不生成」 |
| 审计表漏写 COLLATE（`utf8mb4_0900_ai_ci` vs 库内 `utf8mb4_unicode_ci`） | 对账 SQL 每轮抛错 → 写入链退化成「只投不认」，且**日志里只有一行 Illegal mix of collations** |
| 429 若被 `status / 100 == 4` 一刀切成毒消息 | 晚高峰的新偏好**成批永久消失**（铁律 3 的存在理由） |

这三条的共同点是：**编译通过、启动成功、常规操作不报错**，只在特定输入/特定时序下静默失效。
所以本方案的第一条原则是：

> **只测「正常路径能跑通」等于没测。** 用例的重心必须放在**失败路径**与**边界值**上。

## 二、现状盘点

### 2.1 已有覆盖（不重复建设）

| 文件 | 用例数 | 性质 |
| --- | --- | --- |
| `GraphitiContractTest` | 21 | 契约层（B0）：请求体包装、字段陷阱、召回顺序、输入防御、时间解析、429/403 可识别 |
| `GraphitiWriteChainDiagnosticTest` | 5（有序） | **实机端到端**：夹具 → 扫描投递 → CAS 占位 → 对账闭环 → 锚点/排序键 → 暗雷 1 正面回归 |

`GraphitiWriteChainDiagnosticTest` 的价值已经验证过：它一轮就抓出了上述 2 个 P0。它同时是 B4 的回归守卫，**必须保持可跑**。

### 2.2 环境约束（决定了测试的写法）

| 约束 | 影响 |
| --- | --- |
| `pom.xml` 只有 `spring-boot-starter-test`（含 JUnit5 / Mockito / AssertJ） | **没有 Testcontainers、没有 Awaitility、没有 H2** → 集成测试只能打真环境 |
| 真环境是**共享的单机 Docker**（MySQL 192.168.88.130:3306、RabbitMQ :15672、Graphiti :8088） | 集成测试必须**自带夹具清理**与**断网门闸**，否则会污染真实用户数据 |
| Graphiti **有状态且服务端零去重** | 夹具 ID 必须是探针专属前缀，且**开跑前先清空探针 group**（否则上一轮 episode 会让断言秒过 → 假阳性） |
| 工具侧**起不了长驻服务** | 任何需要「起后端再手工点」的验证都不可靠；一律写成 `mvn test` 可前台跑完的形态 |

### 2.3 基础设施缺口（建议补，但不阻塞本方案）

| 缺口 | 后果 | 建议 |
| --- | --- | --- |
| 无 `@Tag` 分层 | `mvn test` 会连实机集成测试一起跑 → CI/无网环境必红 | 给集成测试加 `@Tag("integration")`，默认 `mvn test` 只跑 L0/L1 |
| 无 Awaitility | 异步等待靠手写 `while + sleep`（现有 `awaitTrue`） | 可选项，现有写法已够用 |
| 无测试专用配置 | 集成测试靠 `@SpringBootTest(properties={...})` 逐个覆盖 | 可加 `src/test/resources/application-test.yaml` |
| **3 项既有失败测试**（见 §七） | 让「全绿」这个信号失真 | 必须先处置，否则新用例的失败会被淹没 |

## 三、分层策略

按「依赖成本 × 失败概率」排列，**下层先做、必须做全**：

```
L0 纯函数单测        零依赖 / 毫秒级 / 必进 CI          ← 静默数据丢失类缺陷的主战场
L1 组件单测（Mockito）无容器 / 秒级 / 必进 CI          ← 状态机与分支路由
L2 集成测试（真环境） 需共享 Docker / 分钟级 / 手动或夜间  ← 只有它能证明「真的能落库」
L3 故障注入（混沌）   需停容器 / 分钟级 / 手动           ← 证明「挂了会怎样」
L4 实机取证（附录 D） 一次性 / 出数据不留代码             ← 把设计文档的假设钉成事实
```

### L1 —— 组件单测（Mockito，新增 4 个测试类，约 35 用例）

#### L1-1 `GraphitiWriteConsumerTest` ★最高优先

> 依赖全 mock：`GraphitiMemoryClient`、`GraphitiWriteStateMapper`、`GraphitiWriteAuditMapper`。

| 7 | RETRYABLE attempt=2 | 回滚 + 进档 2（10min） |

#### L2-3 `GraphitiReplayAndConfirmIntegrationTest`（新增，需真库）

L1 用 mock 验分支，这里验**真 SQL 能跑通**（P0-2 的类型：SQL 语法/排序规则/时区问题只有真库能暴露）：

| # | 场景 | 期望 |
| --- | --- | --- |
| 1 | 造一条 `dispatched_at IS NULL` 的待补投行 → 跑 `replay()` | 该行被投递进 `write.queue`（用 Admin API 查 `messages_ready` 增量） |
| 2 | ★ 写一条审计行后跑 `replay()` | 该消息**不再被捞出**（暗雷 1 正面回归，§L2-1 已部分覆盖） |
| 3 | ★ 造一条 `dispatched_at = NOW()` 的确认目标 → 跑 `confirm()` | 因 3 分钟门槛**不被选中**（验证 SQL 时间谓词真的生效） |
| 4 | ★ 把 `dispatched_at` 前挪 4 分钟 → 跑 `confirm()` | 被选中；锚点不存在时 `confirm_rounds++` |

> #5 / #6 是本方案里**最直接针对两个 P0 的回归**，必须有。

### L3 —— 故障注入（混沌，手动，价值最高）

> 这些用例只有一条命令的复杂度（停/起容器），但能验证整条链的「降级姿态」。

| # | 操作 | 期望观测 |
| --- | --- | --- |
| 1 | 停 `memory_graphiti` 容器 → 投递一条常规消息 | `dispatched_at` 先被占、随后**回滚为 NULL**；消息进 retry 档；日志出现 RATE_LIMITED/RETRYABLE 分类 |
| 2 | 停 Graphiti 后连投 N 条（N > 背压阈值） | `graphiti.backpressure.active = 1`；扫描层**不再投递**但**照常 ack**；`graphiti.write.queue.depth` 上涨 |
| 3 | 停 Graphiti 期间投一条**高危词**消息 | **仍被投递**（快通道不受熔断影响）—— 这是熔断语义的核心断言 |
| 4 | 停 Graphiti 期间跑 `replay()` | **整轮跳过**（不自我加码） |
| 5 | 恢复容器 → 等积压排空 + 观察期结束 | 自动解冻（WARN 日志）；`ReplayJob` 把被跳过的消息补投；最终 `synced_at` 全部非空 |
| 6 | ★ 停 Graphiti 期间跑 `confirm()` | 轮次**不被消耗**（否则短暂宕机 → 全量 `CONFIRM_TIMEOUT` 误隔离） |

## 六、执行方式与验收标准

### 6.1 分层执行

```bash
# T1+T2：零依赖，CI 默认跑这层
mvn -o test -Dtest='Graphiti*Test' -Dsurefire.failIfNoSpecifiedTests=false

# T3/T4：需真环境（Graphiti 不可达时自动 Assumptions 跳过）
mvn -o test -Dtest='GraphitiWriteChainDiagnosticTest,GraphitiMqTopologyTest,GraphitiReplayAndConfirmIntegrationTest' \
  -Djava.io.tmpdir=D:/ruoyi/RuoYi-Vue-master/Mini_Nodepad/target/tmp \
  -Dsurefire.failIfNoSpecifiedTests=false
```

> ⚠️ `-Djava.io.tmpdir=.../target/tmp` 不是可选项：本机 `C:\WINDOWS\TEMP\surefire-*` **建不出临时目录**，
> 会让测试 JVM 的 `System.out` 整段丢失（曾因此拿不到附录 D #7 的实测数字）。

### 6.2 验收标准

| 项 | 标准 |
| --- | --- |
| T1+T2 | 用例数 ≥ 90，**全绿**，单轮 < 30s，无外部依赖 |
| T3+T4 | 全绿；Graphiti 不可达时**显示 skipped 而非 failed**（门闸生效） |
| 幂等性 | 同一套集成测试**连跑两次结果一致**（验证夹具清理彻底） |
| 无残留 | 跑完 `_b1_e2e.mjs check` 与图谱 group 查询均为空 |
| 可观测 | 熔断触发/恢复、重试分档、审计落表三者均能在日志里被单独 grep 到 |
