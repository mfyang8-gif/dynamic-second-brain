**设计说明**

- 长度 128 足够（标题限 40 字内，留足余量）。

## 四、新增：`ai/aiservice/ArtifactTitleAssistant.java`

完全对齐现有 `QueryRewriteAssistant` 规范：接口式声明、`@SystemMessage` / `@UserMessage` / `@V`、无状态无记忆、纯文本返回。

```java
package com.yangmf.mini_nodepad.ai.aiservice;

import dev.langchain4j.service.SystemMessage;
import dev.langchain4j.service.UserMessage;
import dev.langchain4j.service.V;

/**
 * 工件动态命名助手（两阶段）。
 *   阶段一 draftTitle：流式开始时，仅凭「用户提问 + 类型」给出场景化暂定名，供前端卡片占位。
 *   阶段二 refineTitle：拿到完整工件内容后，精修成具象标题，落库到 dynamic_title。
 * 与 QueryRewriteAssistant 同构：轻量、无记忆、纯文本输出。
 */
public interface ArtifactTitleAssistant {

    @SystemMessage("""
    你是知识库工件的命名助手。根据用户提问与工件类型，给出一个【场景化暂定名】。

    【严格规则】
    1. 必须点明具体研究的对象或主题，禁止出现"文档""笔记""资料""内容""知识库"这类空词
    2. 长度 8~18 个汉字，不带书名号、不带引号、不加句号
    3. 直接输出名字本身，禁止任何前缀、解释、换行
    4. 使用与提问相同的语言

    【示例】
    提问"群体心理是怎么回事" + 工件类型"思维导图" → 群体心理学核心脉络
    提问"总结第三章" + 工件类型"测验" → 第三章要点自测
    """)
    @UserMessage("""
    工件类型：{{type}}
    知识库名称：{{bookName}}
    用户提问：{{question}}
    """)
    String draftTitle(@V("type") String type,
                      @V("bookName") String bookName,
                      @V("question") String question);

    @SystemMessage("""
    你是知识库工件的命名助手。现在已拿到工件的完整内容，请把它精修成一个【具象化标题】。

    【严格规则】
    1. 要有概括力与文学质感，像一本书或一份报告的正式标题
    2. 长度 8~20 个汉字；若采用主副标题式表达，用全角冒号连接（例：狂热与博弈：群体心理的脉络）
    3. 不带书名号、不带引号、不加句号
    4. 只输出一行标题本身，禁止任何解释、前后缀
    5. 使用与提问相同的语言
    """)
    @UserMessage("""
    工件类型：{{type}}
    用户提问：{{question}}
    暂定名：{{draft}}
    工件内容节选：
    {{content}}
    """)
    String refineTitle(@V("type") String type,
                       @V("question") String question,
                       @V("draft") String draft,
                       @V("content") String content);
}
```

### 8.3 新增私有方法（全部在 `StudioServiceImpl` 内）

```java
    /** 内容节选上限：控制精修调用的 token 成本 */
    private static final int TITLE_DIGEST_MAX = 1500;
    /** 标题兜底长度上限 */
    private static final int TITLE_MAX_LEN = 40;

    /**
     * 阶段一：暂定名。
     * 与主生成并行执行，纯 best-effort —— 任何异常只记 warn，绝不影响主生成与落库。
     */
    private void applyDraftTitle(StudioArtifact artifact, ArtifactType type,
                                 BaseStudioRequest request, Long userId) {
        try {
            String draft = titleAssistant.draftTitle(
                    type.getDescription(),
                    bookNameOf(artifact.getBookId()),
                    StringUtils.hasText(request.getTopic()) ? request.getTopic() : "未指定主题");
            pushTitle(artifact, userId, sanitizeTitle(draft), "暂定名");
        } catch (Exception e) {
            log.warn("暂定名生成失败，前端将回退 topic | artifactId={}", artifact.getId(), e);
        }
    }

    /**
     * 阶段二：精修名。主生成完成后、SUCCESS 落库前调用，同样 best-effort。
     * 失败时保留阶段一写入的暂定名（或 NULL，由前端回退 topic）。
     */
    private void applyRefinedTitle(StudioArtifact artifact, ArtifactType type,
                                   BaseStudioRequest request, ArtifactPayload payload, Long userId) {
        try {
            String refined = titleAssistant.refineTitle(
                    type.getDescription(),
                    request.getTopic(),
                    artifact.getDynamicTitle(),
                    digestOf(payload));
            pushTitle(artifact, userId, sanitizeTitle(refined), "精修名");
        } catch (Exception e) {
            log.warn("精修命名失败，沿用暂定名 | artifactId={}", artifact.getId(), e);
        }
    }

    /** 统一的「写库 + SSE 推送」出口，保证命名只走一条路径 */
    private void pushTitle(StudioArtifact artifact, Long userId, String title, String stage) {
        if (!StringUtils.hasText(title)) {
            return;
        }
        artifact.setDynamicTitle(title);
        artifactMapper.updateById(artifact);
        workspaceSseService.pushToUser(userId,
                WorkspaceEvent.artifactTitled(artifact.getId(), title));
        log.info("Studio {} 已就绪 | id={}, title={}", stage, artifact.getId(), title);
    }

    /** 取书名用于命名上下文；取不到不致命，返回空串 */
    private String bookNameOf(String bookId) {
        try {
            BookVO book = bookService.getBookById(bookId);
            return book != null && book.getName() != null ? book.getName() : "";
        } catch (Exception e) {
            log.warn("取书名失败，命中降级 | bookId={}", bookId, e);
            return "";
        }
    }

    /** 清洗模型输出：去引号/书名号/换行/尾句号，并压到长度上限 */
    private String sanitizeTitle(String raw) {
        if (!StringUtils.hasText(raw)) {
            return null;
        }
        String t = raw.strip()
                .replaceAll("[\\r\\n]+", " ")
                .replaceAll("^[\"'\u201c\u201d\u2018\u2019\u300a\u300b\\s]+", "")
                .replaceAll("[\"'\u201c\u201d\u2018\u2019\u300a\u300b\\s]+$", "")
                .replaceAll("[。.]+$", "")
                .strip();
        return t.length() > TITLE_MAX_LEN ? t.substring(0, TITLE_MAX_LEN) : t;
    }

    /** 工件内容节选，供精修命名参考 */
    private String digestOf(ArtifactPayload payload) {
        try {
            String json = objectMapper.writeValueAsString(payload);
            return json.length() > TITLE_DIGEST_MAX ? json.substring(0, TITLE_DIGEST_MAX) : json;
        } catch (Exception e) {
            log.warn("工件内容序列化失败，精修将只依据提问 | type={}", payload.getClass().getSimpleName(), e);
            return "";
        }
    }
```

### 8.4 事件时序（保证顺序）

```
POST /studio/...              → 201 { artifactId }
   ↓ 异步
ARTIFACT_TITLED (暂定名)      ← 阶段一，约 0.5~2s
ARTIFACT_PROGRESS × N         ← 现有 Ticker 轮播（不变）
ARTIFACT_TITLED (精修名)      ← 阶段二，主生成返回后
ARTIFACT_COMPLETED            ← 现有语义不变
```

### 8.5 兜底矩阵

| 场景 | `dynamic_title` | 前端显示 |
|---|---|---|
| 两阶段均成功 | 精修名 | 精修名 |
| 阶段一成功、阶段二失败 | 暂定名 | 暂定名 |
| 阶段一失败、阶段二成功 | 精修名 | 精修名 |
| 两阶段均失败 | `NULL` | 回退 `title`（用户填的 topic） |
| 主生成失败 | 保留已达成的名字 | 收到 `ARTIFACT_FAILED` |

**关键纪律**：命名链路全程 `try/catch` 收敛在私有方法内，**绝不向上抛**，因此不会影响现有生成失败判定、`markFailed` 与重试（`@Retryable`）逻辑。

| `thinking` | 正在思考中... | 正在生成回答... | `GENERATING_RESPONSE...` | 倾墨落笔中... |
| 流结束 | — | 淡出 → 正文 | `> RUN_COMPLETED` → 正文 | 淡出 → 正文 |

> ⚠️ **需要你拍板的一点**：`EXEC_PARSE_INPUT` / `正在章回构思` 这类**风格化文案**，我建议由**前端按主题映射 phase** 得到（后端继续只推语义 phase）。理由：主题是前端的表现层概念，后端不该感知；否则要把主题一路透传到 `ChatStreamService`，污染分层。
> 若你坚持后端直接推风格化文案，后端改动会扩散到 `ChatStreamService`（+主题入参），我可以照做，但会破坏现有分层。
