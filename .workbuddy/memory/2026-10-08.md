## Mini-NotebookLM 第四批：对话流（后端 4 处缺陷定位 + 修复 + 端到端实测）

用户要求「先对话流」。结论：**后端对话流从未跑通过**，被 4 个互相叠加的缺陷锁死，
任修其一都到不了终点。全部定位并修复，已用独立端口 8083 临时实例端到端验证通过。

修复清单（完整 patch 文档见 `mini-notebooklm-web/docs/后端对话流修复清单.md`）：

1. **`ChatStreamService` ThreadLocal 被虚拟线程切断（假 401）**
   `BaseContext` 是 `ThreadLocal`，由 JWT 拦截器写在 Tomcat 请求线程；但
   `chatStream()` 整段跑在 `Thread.startVirtualThread(...)` → `getCurrentId()` 读到 null →
   `UnauthorizedException` 被 `catch (MiniNotePadException)` 兜住 → 伪装成
   `BAD_REQUEST 未登录或登录已过期`。同一原因也让 `aiTaskExecutor` 里的 `persistMessages` 线程取不到 userId。
   修法：请求线程先捕获 `userId`，工作线程内 bind + `finally remove`，并把 `userId` 作为形参
   贯穿 `handleNonRagChat/handleRagChat/persistMessages`。
   （不用 `InheritableThreadLocal`：线程池化线程只在创建时继承，之后不更新，显式传参才稳）

2. **`MainChatAssistant` 缺 `@UserMessage`**（langchain4j 1.15.0 校验变严）
   多参数方法里每个参数都必须带 `@V`/`@UserMessage`/`@MemoryId`/`@UserName`，
   否则**调用时**由动态代理抛 `IllegalConfigurationException` → 被最外层 catch 成
   `SYSTEM_ERROR 系统异常`（看起来像系统故障，其实是接口定义不合格）。
   两个 `chat(...)` 重载的最后一个参数补 `@UserMessage`。

3. **`SuggestionAssistant.generateSuggestions` 参数缺 `@V`** →
   `SuggestionService` catch 后降级空数组 → **追问 chips 永远不出现**（且不报错）。

4. **`QueryRewriteAssistant.rewrite` / `ContextSummarizer.summarizeIncremental` 参数缺 `@V`** →
   分别被 `QueryRewriteService` / `ChatSummaryService` 静默降级 →
   **查询改写（指代消解/子查询拆分）与增量摘要静默失效**。

已核查全部 12 个 AI Service：`Quiz/Flashcard/Mindmap/Report/Presentation` 五个 Studio +
`PageAssistant`/`GeneralAssistant`/`IntentRouter` 都是单参数写法，**无此问题**。

🔴 **唯一非代码问题：`application-local.yaml:11` 的 `streaming-chat-model.api-key: 你的火山引擎Key` 是占位符**
（该文件其余密钥都是真的）。`MainChatAssistant` 用的流式模型 = 火山方舟 ARK doubao。
被当成 Header 值 → `IllegalArgumentException: invalid header value: "Bearer 你的火山引擎Key"`。
- 为什么别的 AI 功能正常：`AssistantConfig` 里除 `streaming-chat-model` 走 ARK，**其余全走百炼 qwen**，
  而百炼 Key 有效 → 这就是 `ingest` 的 AI 处理一直能成功的原因。

### 又一个环境事实（重要，之前踩空过）
`application.yaml:6` 有 `spring.config.import: optional:classpath:application-local.yaml`，
**无条件加载**，与 `spring.profiles.active=dev` 无关。所以 local 配置一定会生效并覆盖
